## Working end-to-end Sandbox run

1. Follow [README.md](../README.md) to start the local Next app, worker, and pinned Qwen model. Use PostgreSQL locally or the initialized Render Free PostgreSQL database described in [RENDER_HACKATHON.md](RENDER_HACKATHON.md). Use a new synthetic demo account at `http://localhost:3000/`, with Sandbox credentials configured and fixture providers disabled.
2. Search Channel3 for a bounded query such as “study timer” and confirm the UI says **Live Channel3 response**. Show its source attribution and indicative offer without following a retailer checkout link. This search is separate from the demo-store reward currently used by the purchase flow.
3. Select the synthetic notebook reward. Save a one-day content-based database-index goal whose date includes today in the chosen timezone; approve its exact item, variant, seller, window, synthetic destination, USD total cap, and displayed `local_llama` reviewer/model. Use a rubric that asks for lookup behavior and write/storage trade-offs rather than an unobservable study-duration claim.
4. Use **Create one-time store code** in the app. In a separate browser tab open `http://127.0.0.1:3000/store`, enter the code, choose the notebook, and save the synthetic cart. Return to the app and choose **Use saved cart for this reward**; that links this exact store session to the active purchase intent. The combined browser sequence passed with the Render-backed account. This does not prove Kernel profile persistence. Use only fictional destination details.
5. Back in the app, submit a substantive note that explains how a B-tree index speeds an email lookup and adds write work and storage. Let the worker run the actual Qwen review, then refresh the dashboard. Show `local_llama`, the accepted verdict, and **1 of 1** distinct day.
6. Choose **Continue to PayPal Sandbox** and approve the $22.68 Notebook set order with a US Sandbox Personal test buyer. PayPal redirects to the app. Choose **Complete PayPal Sandbox capture** while the 15-minute frozen quote/lease is valid. Show the app's `CONFIRMED` state and synthetic receipt. The verified run used order `1AD52467A58843710` and capture `65X65580W2293373U`, both `COMPLETED` on PayPal REST reads with the expected amount, merchant, and reference. No retailer order or live charge occurred.
7. If rehearsing permission revocation, use a **fresh goal cycle**. Revoke before the worker commits, refresh, and show that a new commit is refused. Do not represent a revocation after an in-flight provider call as canceling that call.
