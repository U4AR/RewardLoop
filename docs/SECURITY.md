# Security and demo boundaries

RewardLoop is a hackathon prototype. Its Sandbox-only configuration is a hard boundary: configuration validation requires `PAYPAL_ENV=sandbox`, the exact `https://api-m.sandbox.paypal.com` REST host, and `PAYMENT_PROVIDER=paypal_sandbox`. No live PayPal mode, retailer checkout, card vault, shipping, or payout route exists. Fixture responses are allowed only on localhost and are visibly labelled; they cannot satisfy a PayPal Sandbox proof.

The app authenticates an owner before ordinary state-changing requests and scopes goal, permission, evidence, wallet, and purchase rows to that owner. A wallet connection grants no purchase permission. The immutable permission binds goal/rubric version, app-owned demo SKU and approved variants, seller, quantity, USD all-in cap, synthetic destination, window, alternatives, and payment connection. Revocation blocks a new commit. The deterministic backend counts distinct qualifying dates and checks the exact current quote, inventory version, active permission, one-intent-per-cycle invariant, business window, and wallet before persisting a PayPal operation. Model output and mock-store page content cannot call PayPal or widen the instruction.

The quote reservation and frozen payment operation share a database transaction. A provider timeout is treated as unknown; the system must reconcile rather than generate a replacement charge. Completed captures require an authoritative Sandbox response with expected merchant, USD amount, order reference, and capture ID. Webhook handling is not yet implemented and must verify PayPal's transmitted signature before updating state.

Saved payment tokens are encrypted at rest with `DATA_ENCRYPTION_KEY`; the key and provider secrets are never client fields. `.env.local`, local database files, and build caches are ignored by Git. Setup-token sessions are user-bound, expiring, and single-use. Browser Live View, CDP URLs, session cookies, and API keys are bearer capabilities and must not appear in logs, a public video, or a repository. The mock store runs on a distinct hostname with host-only cookies and no app/admin credentials.

Known limits: no production identity verification or fraud program, no deployed HTTPS callback or verified PayPal webhook, no observed Vault capability, no proven multi-user load isolation, and no completed external security review. A local fixture run is development evidence only. Public judging must use an isolated demo account and redacted provider records. See [PAYPAL_SANDBOX](PAYPAL_SANDBOX.md), [ARCHITECTURE](ARCHITECTURE.md), and [BUILD_STATUS](BUILD_STATUS.md).
